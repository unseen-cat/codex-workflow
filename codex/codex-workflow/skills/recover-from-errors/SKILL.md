# Recover From Errors

Use this skill when repeated failures start to pull the work away from the original goal.

The goal is to stop guessing, re-check the plan, and fix the specific problem that is actually blocking progress.

## Recovery steps

1. Re-read the current plan.
2. Decide whether the failing action was actually part of the plan.
3. If it was planned, fix the specific issue and continue.
4. If it was not planned, stop using that path and return to the plan.

## Rules

- Do not generalize from a failure into a broad rewrite.
- Do not keep retrying random alternatives.
- Do not introduce extra scope to "make it work."
- Do not ignore repeated failures.

## What good recovery looks like

- The blocking assumption is named clearly.
- The plan is checked before the next tool call.
- The fix is narrow and directly tied to the failure.
- The work returns to the original objective instead of drifting.
