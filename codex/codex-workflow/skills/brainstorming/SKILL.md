# Brainstorming Ideas Into Designs

Use this skill to turn a rough idea into a concrete direction before any code changes.

Start by reading the current project state. Ask one focused question at a time when the goal, constraints, or success criteria are unclear. When external facts matter, verify them with current sources instead of relying on memory.

## Process

### 1. Understand the context

- Check the relevant files, docs, and recent changes first.
- Note assumptions, risks, and what is still unknown.
- If clarification is needed, ask a single question and wait.

### 2. Explore options

- Propose 2 or 3 workable approaches.
- Explain the tradeoffs in plain language.
- Lead with the option you recommend and why.

### 3. Verify facts

- Use web search when the answer depends on current product behavior, docs, standards, prices, schedules, or other changeable facts.
- Check source quality and recency before using the result.
- If sources conflict, prefer the most authoritative and recent one.

### 4. Present the design

- Break the design into small sections.
- Cover architecture, components, data flow, errors, and tests.
- After each section, check whether it still matches the user's intent.

### 5. Keep the plan aligned

- If a plan is already active, update it with the new direction instead of drifting.
- Do not mix implementation into exploration.

## Principles

- One question at a time.
- Prefer simple choices over complicated ones.
- Treat uncertain external facts as hypotheses until verified.
- Keep the user oriented with a clear recommendation.
